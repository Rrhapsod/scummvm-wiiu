# Controller / FMV candidate — October 18, 2026

This is a test candidate, not a stable release. I confirmed save-name editing
works with the October 13 build. I still hear audio interruptions and see
micro-stutters in The 11th Hour. The Pro Controller keyboard/HOME report came
from an older build, with no game name or log; it is not a confirmed regression
of the October 13 build. These exact new binaries need Wii U testing.

## Native keyboard

The SDL keyboard previously selected GamePad input from the output-window
flags. ScummVM opens one gameplay controller, so a GamePad connected later
could also go unread. This candidate:

- Selects the controller from actual activity/available samples, including
  Pro/Classic/Wii Remote channels, instead of the display flags.
- Polls keyboard input for controllers not supplied by SDL's opened joystick,
  so connecting a GamePad later can supply touch input. Supplied samples are
  reused rather than read twice in that keyboard calculation.
- Draws the TV keyboard view for a remote/Pro controller and the DRC view for
  GamePad input; the normal mirrored application layout is retained.
- Releases application buttons/axes while native input is active, including
  animations, and suppresses held confirmation buttons until released.
- Cancels and destroys native keyboard state before foreground graphics
  resources are released for HOME/background transitions. Pending text is
  not committed. The keyboard is recreated lazily when requested again.

These changes target the source-confirmed routing/lifetime problems. I cannot
claim they resolve the reported shutdown hang without reproducing it on Wii U.
This does not add arbitrary third-party/USB controller support to swkbd or
change ScummVM's selection of the controller used during gameplay.

## Groovie movies

The supplied 11th Hour log reaches a normal return to the launcher. It records
several first/still frames at 130–175 ms of decode plus drawing and a separate
1160 ms decode sample. Most movie frames are absent because the old per-frame
trace threshold was 100 ms. That does not establish steady playback speed or
prove a codec/audio-device failure.

Unscaled, unmasked rows with no overlay compositing now use a bulk copy only
after checking every source pixel is fully opaque. Transparent, partially
decoded, scaled, masked and overlay paths retain the original blending.
The pixel-equivalence tests cover both byte orders. No movie frames are
dropped and no playback speed, audio format or audio-buffer timing is changed.

New bounded main-thread reports summarize 120 ROQ frames: total decode/draw/
wait time, maximum work and between-call gap, frames over their timing budget,
empty audio-queue observations and current queued chunks. These are diagnostic
observations, not exact audio-underrun counts. Reports stop after 24 windows
per player. The existing slow-frame/file markers remain; logging affects timing.
The rendering speedup and its effect on audio need console measurement.

Clandestiny/Tender Loving Care/Uncle Henry community cases remain unverified.
Ogg does not change the ROQ codec. Earlier Curse/QFG4, renderer/timer and text
editing fixes, Ogg/Vorbis, MP3 and MT-32 are retained.

## Install and test

1. Back up executable, configuration and saves. Extract the complete Aroma
   ZIP at the SD root. No INI edit is required. Keep the previous ZIP for rollback.
   The RPX package is still experimental and unverified on non-Aroma setups.
2. Check the startup log says `input/FMVs candidate 20261018`.
3. Launch with only a Pro Controller, open a save-name field, navigate and
   enter a short name, confirm, cancel and reopen. Release buttons between
   actions. Repeat by connecting the GamePad while the keyboard is open and
   trying touch. Test other supported controllers separately if available.
4. Repeat launching with GamePad only, including existing-name edit/erase.
   Test normal Quit. Separately test HOME while the keyboard is visible,
   returning to the app and reopening the field, then HOME -> Close Software.
   HOME cancels unconfirmed keyboard text in this candidate.
5. Play the same 11th Hour intro and interactive movie scenes for at least
   30 seconds each. Compare stutters/audio cuts with October 13. Try skipping
   a movie, saving/loading and repeated return/reopen. Test 7th Guest too.
6. Retest Curse/QFG4 loading/audio and existing MP3/MT-32/Ogg cases.

Copy `SD:/scummvm/scummvm-compat-diagnostic.log` after each test. Logging
appends, so keep the full file. Record controller type/channel, whether the
GamePad was off at launch, game/scene and exact last action. For a genuine
hang, stop repeated hard resets and copy the log after the console is fully
off, before relaunch. Flush/fsync cannot guarantee persistence after power loss.

No games, ROMs, saves, configuration or user logs are bundled.

## Rebuild

Apply `sdl2-swkbd-controller.patch` to the prepared devkitPro SDL tree after
the existing input, lifecycle, renderer and zero-timeout patches. Rebuild and
install SDL into the local SDK (preserve the old library for rollback), then:

```sh
bash backends/platform/sdl/wiiu/build-input-fmv-test.sh
```

Default output: `../build-scummvm-wiiu-input-fmv-20261018/`. The new SDL static
archive affects future local builds, not the already packaged older binaries.
