# Wii U FMV conversion test — October 18, 2026, revision 2

This is a test candidate, not a stable release. I still hear interrupted audio
and see stuttering in The 11th Hour with the earlier input/FMV candidate.
The new log confirms that build was installed. In sustained 30 fps sequences,
120 frames took about 5.8 seconds to draw, plus about 1.1 seconds to decode.
That exceeds the 4-second budget. Some audio queue observations were empty.
These observations do not yet identify every source of audio interruptions.

## What I changed

- I added a specialized SDL RGBA8888-to-RGB565 surface conversion. Groovie's
  32-bit pixels previously used SDL's generic conversion to the intermediate
  16-bit screen. The new path preserves the same RGB values and discards alpha
  only for a non-blended RGB565 destination, just as the old path did.
- I added bounded main-thread timing for surface conversion, software scaling
  and cursor drawing, texture upload, render submission and presentation.
  These appear as `VIDEO stages` every 120 presented 32-bit game frames, up to
  24 reports per video mode. No logging occurs in the audio callback.
- I reset incomplete ROQ timing windows when loading another movie, so frame
  rates and audio queue samples from different movies are not mixed.

I did not change audio buffering, movie timing, codecs, frame skipping, GX2
synchronization or the SDL renderer's resource lifetime. Previous keyboard,
Curse/QFG4, Ogg/Vorbis, MP3 and MT-32 changes remain included. This candidate
does not establish that the Pro Controller/HOME report is resolved.

The specialized conversion is source-verified and can be checked against the
original SDL dispatcher with `tests/blit/run.py`. A host speed comparison is
not a Wii U benchmark; the new console log is needed to measure the benefit.

## Installation and focused test

1. Back up my configuration, saves and previous executable. Extract the whole
   Aroma ZIP at the SD root. No INI changes are required. Use the RPX ZIP only
   for experimental non-Aroma testing; that environment remains unverified.
2. Start ScummVM fresh and launch The 11th Hour. Play the same intro and an
   in-game movie with speech for at least 30 seconds each. Compare picture,
   speech, music and synchronization, and check colors and the mouse cursor.
3. Open/close the ScummVM menu, return to the launcher, reopen the game and
   quit normally. If possible, briefly check a previously working game too.
4. Copy `SD:/scummvm/scummvm-compat-diagnostic.log` and report which movie still
   stutters, whether audio improved, and any color/menu regression. Look for
   `FMV blit candidate 20261018-r2` near the latest session header.

I have not yet validated this candidate on real hardware. If the console
hangs, avoid repeated hard resets and preserve the log before another launch.
Games, save files, configuration and MT-32 ROMs are not included.

## Rebuilding

Apply `sdl2-rgba565-blit.patch` to the existing devkitPro SDL tree after the
previous patches, rebuild/install SDL, activate the Wii U SDK and run
`bash backends/platform/sdl/wiiu/build-fmv-blit-test.sh`. The script creates a
separate build directory and retains the earlier engine/codec profile.
