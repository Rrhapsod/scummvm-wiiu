# SDL timer candidate fix — October 12, 2026

This is a candidate fix for testing, not a stable release or a hardware-confirmed
repair. I have not tested these exact binaries on my Wii U yet.

## Evidence and scope

My October 12 Curse log shows SDL timer callbacks stuck at 974/974 and digital
iMUSE callbacks stuck at 6/6 across more than 30 seconds while the game keeps
running. Completed entry/exit counts narrow the failure to outside those
callbacks. Audio is enabled, unmuted, and the original bundles open correctly.

The Wii U SDL semaphore implementation calls SDL_SemTryWait for a zero timeout
but discards its result and continues into the alarm/condition-wait path. SDL's
timer worker uses zero-timeout waits when callback processing consumes the
remaining delay. The patch returns the try-wait result immediately, as required,
without arming an alarm, blocking, or attempting to consume a second token.
This is a source-confirmed defect compatible with the log, not yet proof that
it is the only cause of the silent audio. Positive-timeout behavior is unchanged.

This build keeps the October 12 callback counters, persistent log, all enabled
engines/codecs and previous renderer/keyboard fixes. No audio decoder, mixing,
SCI resource-loading or filesystem behavior was changed. No games, ROMs,
configuration, saves or diagnostic logs are bundled. Non-Aroma RPX is unverified.

## Install and test

1. Back up the installed executable, configuration and saves. Keep the earlier
   diagnostic ZIP for rollback. Extract the complete Aroma ZIP to the SD root,
   replacing the existing executable instead of adding a duplicate entry.
2. No INI changes are required. The startup log must identify **timer fix
   candidate 20261012**. Logging still appends to
   **`SD:/scummvm/scummvm-compat-diagnostic.log`**.
3. Test Curse: play the intro, then reach interactive gameplay and play for at
   least 30 seconds. Check music, speech and effects on TV/GamePad. Return to
   the launcher, reopen Curse and repeat. Then Quit normally and copy the log
   as `scummvm-timer-fix-curse.log`. Report missing audio even if it is partial.
4. If stable, check another previously working game's sound, save/load,
   keyboard confirm/cancel and repeated return/reopen. Keep saves backed up.
5. Optionally retest QFG4 DOS/Windows from fresh application launches. Allow
   up to five minutes for startup before treating a black screen as a hang.
   This candidate does not optimize its resource scan. Preserve a separate
   log and measure time from Start until the intro or title appears.
6. On a genuine unresponsive hang, avoid repeated forced resets. Once the
   console is fully off, remove the SD and copy the log on the PC before
   relaunching. Flush/fsync improves persistence but cannot guarantee it after
   forced power-off; pending SD writes can still be damaged.

Counters should keep advancing during the bounded main-loop audio snapshots.
Intro playback may delay snapshots. Tracing changes timing; apparent success
still needs repeated hardware tests before release.

## QFG4 startup findings

I confirmed both CD/DOS and CD/Windows editions open and are playable. Although
my initial estimate was about 90 seconds, the supplied diagnostic log measures
about **156 seconds** from resource-init entry to game execution for each
edition. Most of that time is in the second source scan, which indexes audio.
Detailed logging also adds overhead, but the long interval continues after
the detail limit is reached.

The SCI resource validator repeatedly queries the same volume's size. The
POSIX stream calls fstat each time, with seek-to-end/restore as a fallback.
Reusing the validated size for a read-only volume during initialization is a
targeted optimization to investigate separately, preserving bounds checks and
handling source/disc changes correctly. No speedup is claimed or included here.

## Rebuild

Apply `sdl2-timer-zero-timeout.patch` in the prepared devkitPro SDL tree, on top
of the existing keyboard/renderer patches. Rebuild/install SDL and relink in
a fresh ScummVM build directory; changing ScummVM alone is not sufficient.
After activating the prepared SDK, run:

```sh
bash backends/platform/sdl/wiiu/build-timer-fix.sh
```

Default output: `../build-scummvm-wiiu-timer-fix-20261012/`.
Earlier packages remain unchanged, but new local builds use the updated SDK.
The pre-fix SDL archive is backed up locally; see BUILD-INFO.txt.

Host regression (actual SDL function with mocked Wii U primitives):

```sh
python3 backends/platform/sdl/wiiu/tests/timer-zero-timeout/run.py ../SDL-devkitpro/src/thread/wiiu/SDL_syssem.c
```

This tests immediate return and token consumption, and contrasts the previous
missing-return implementation. It does not emulate Wii U alarm scheduling.
